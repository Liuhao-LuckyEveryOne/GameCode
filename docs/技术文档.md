## 2. 整体架构

### 2.1 分层结构

```
┌─────────────────────────────────────────────┐
│  大厅层 index.html（顶层文档，持有全局状态）    │
│  · 卡片导航 / iframe 覆盖层 / 音效开关宿主     │
├─────────────────────────────────────────────┤
│  公共库层（所有页面统一引入，先于业务脚本）      │
│  · audio.js      → window.SFX（音效合成）     │
│  · fx.js         → window.FX（渲染特效）      │
│  · fullscreen.js → window.FS（全屏 + 嵌入）   │
│  · gamepad.js    → window.GP（手柄支持）      │
├─────────────────────────────────────────────┤
│  游戏层 7 ×（html + js），通过公共库获得       │
│  音效播放与全屏/嵌入能力，互不依赖             │
└─────────────────────────────────────────────┘
```

### 2.2 依赖规则

- 所有页面按 **audio.js → fx.js → fullscreen.js → gamepad.js → 业务 js** 顺序加载；业务脚本直接消费全局 `SFX` / `FX` / `FS` 对象（gamepad.js 为可选自治库，全局 `GP` 仅暴露连接状态，页面侧零调用）。
- 公共库不反向依赖任何业务脚本；游戏间零共享代码（各自独立目录职责）。
- 全屏与音效的**权威状态由顶层文档（大厅）持有**，iframe 内的子页通过 postMessage 协议同步，见 §3。

### 2.3 嵌入模式通信协议

大厅以 iframe 覆盖层打开游戏页时，URL 自动附加 `?embed=1`（[index.js L1238](../index.js#L1238)）。子页据此判定 `window.parent !== window` 启用嵌入行为：

| 消息类型 | 方向 | 载荷 | 语义 |
| --- | --- | --- | --- |
| `arcade:hello` | 子 → 父 | 无 | 子页就绪报到，触发父页下发当前全屏/音效状态 |
| `arcade:fs` | 父 → 子 | `{ fs: boolean }` | 大厅全屏状态广播，子页进入/退出游戏内全屏 |
| `arcade:save` | 父 → 子 | 无 | 大厅关闭覆盖层（返回游戏厅）前通知子页保存进度镜像快照（2026-11-01 起；0.55s 关机动画窗口内送达，子页收到即调 `saveSnapshot()`，见 §5.1） |
| `arcade:audio` | 双向 | 子→父 `{ act: 'toggle' \| 'vol' \| 'hello' }` 请求（vol 附 `{ ch, idx }`）；父→子 `{ m, b, s }` 全量广播 | 静音开关 + BGM/SFX 档位一体化同步（v2.3 起，取代旧 `arcade:sfx` / `arcade:vol` 四消息；hello 报到亦走本通道，v2.3.1 修正指纹为 `type:'arcade:audio' + act:'hello'`） |
| `arcade:playtime` | 子 → 父 | `{ id, seconds }` | 游玩时长增量上报（2026-11-04 起）：子页 `FX.playtime` 周期上报页面可见期累计秒数，父页 index.js 按游戏 id 累加落盘 `arcade_playtime_<id>` 并即时刷新卡片时长角标（不经公共库协议层——fx.js 发送、index.js 接收，同 `arcade:save` 模式） |

协议实现集中在 [fullscreen.js](../fullscreen.js) 的 `initEmbed()`（子页侧）与 `broadcast()`（父页侧），以及 [audio.js](../audio.js) 的 `applyAudioState / broadcastAudio / muteCore / setVolCore` 一组同步四件套（静音与双通道档位共用单消息通道）。

另外，`arcade:save` 不经公共库——由父页 [index.js closeGame](../index.js#L1179) 直接 postMessage 下发，各游戏 js 自行监听（与 `pagehide` 兜底共同构成进度快照双保存触发，见 §5.1；2026-11-05 起游戏页返回链接移除，原「返回链接 click」触发点随之删除）。

## 3. 公共库详解

### 3.1 audio.js —— 音效引擎（1011 行，v3.0）

全局暴露 **`SFX`** 对象。核心要素：

**三原语合成器**

| 原语 | 实现方式 | 用途 |
| --- | --- | --- |
| `tone()` | OscillatorNode + 指数衰减包络 + 可选滑音（frequency ramp） | 主旋律类音效 |
| `noise()` | 白噪声缓冲 + BiquadFilter 带通 | 爆炸/摩擦类音效 |
| `arpeggio()` | 按 `tone()` 序列定时播放 | 通关/胜利类音效 |

**AudioContext 解锁**：首次用户交互播放"投币双音"（988Hz → 1319Hz），满足浏览器自动播放策略并完成解锁。

**状态模型与同步三件套（v2.3）**：

- **双态合一**：`muted`（静音布尔）+ `vol { b, s }`（BGM/SFX 双通道档位 0~3）合并持久化于 `localStorage['arcadeAudio']`（JSON `{m,b,s}`，默认 `{m:0,b:3,s:3}`）；启动时优先读新键，缺失则从旧键 `arcadeSound` / `arcadeVol` 一次性迁移并删除（老用户档位与开关无损升级）。静音独立于档位——静音不改档、恢复即还原（一键静音无损）。
- `muteCore()`：切换 `muted`，落盘 + `broadcastAudio()`；`setVolCore(ch, idx)`：切档钳位幂等，落盘 + 广播。
- `applyAudioState(v)`：接收远端广播，静默更新本地状态（不回传，避免消息回环）；`broadcastAudio()`：iframe 内向父页发送 `arcade:audio`（协议见 §2.3）。
- **兼容门面**：`SFX.enabled` getter = `!muted`（游戏侧只读接口零改动）；`ensure()` / `warm()` 在静音态直接短路不出声。

**音效命名规范**：`SFX.<前缀><名称>`。通用音效 `uiHover / uiClick / start / gameOver`；业务前缀 `snake`(3 个)、`t`(7 个，俄罗斯方块) + `allClear`(俄罗斯方块全消大奖，无前缀)、`pac`(6 个)、`pin`(6 个)、`bee`(30 个)、`kl`(17 个)、`n1024`(17 个，1024 数字合并)、`card`(7 个，大厅卡片——每游戏一个签名音)。新增音效必须挂到 `SFX` 对象上，禁止散落的全局函数。

**v2 扩展（2026-10-21，四批游戏增强的公共基建）**

- **BGM 三态管理**：`SFX.bgm.start(name) / stop() / pause() / resume() / playing() / sync()`——程序化 chiptune 循环按小节调度（方波旋律 + 贝斯），`start` 同名幂等（重复调用不重启）；7 款游戏各配专属曲目（`snake / tetris / pac / bee / pinball / klotski / n1024`），开局起播、结算停止、暂停 `pause()` 挂起恢复 `resume()` 接续；`sync()` 供全局音效开关切换时同步启停。
- **跨游戏通用音效**：`uiPause / uiResume`（暂停/恢复双音反馈，7 款游戏统一接入——1024 沿用专属 `n1024Pause/n1024Resume`）、`alarm(level)`（危险分级警报，level≥2 双音加重）、`comboUp(level)`（连击升级，音高随等级每级 +70Hz 上探，上限 8 级封顶）、`newRecord`（破纪录上行琶音）、`pinCharge(p)`（弹球蓄力，音高随力度 180→740Hz）、`crtOn / crtOff`（CRT 通电/断电音，与开机白线 / 关机坍缩演出同步）、`klRankS`（华容道 S 级号角，弹珠台 Jackpot 复用）。

**v2.1 增补（2026-10-22，俄罗斯方块三件套配套）**：`tSpin`（T-Spin 判定成功双音：700→1100Hz 上滑短音接 1568Hz 高音确认）、`allClear`（ALL CLEAR 大奖：六连上行琶音接 2093Hz 高音 sparkle 长尾）。

**v2.2 新增（2026-10-22，大厅 BGM + 双通道音量分级）**

- **大厅 BGM 曲目 `lobby`**：曲库第 8 首（bpm 96，双 triangle 声部，bass/lead 各 16 步），大厅初始化即 `SFX.bgm.start('lobby')` 请求播放迎宾曲——浏览器自动播放策略下首次手势前静默待命，由 audio.js 的 `warm()` 首次按下/按键后自动补启；`openGame()` 时 `bgm.pause()` 挂起、`closeGame()` 关机演出启动时 `bgm.resume()` 接续（开关关闭或未请求播放时均为无害空操作）——进出游戏的 BGM 生命周期由大厅单点接线，游戏页零改动。
- **BGM/SFX 双通道 4 档音量分级**：`VOL_STEPS = [0, 1/3, 2/3, 1]` 四档增益，BGM 通道走 `musicOut` 独立分层增益淡入淡出（时间常数 0.25 / 0.12，档 0 时音序器调度 interval 整个挂起零开销），SFX 通道走 `master.gain`（`setTargetAtTime` 0.04s 平滑）；切到非 OFF 的 SFX 档播 660Hz 确认短音（UI 与持久化形态见下文 v2.3 重构）。

**v2.3 重构（2026-10-22，音控统一：单键 + 长按面板）**

- **单键音控 API**：`SFX.muteToggle()` 一键静音/恢复（档位无损，静音/恢复双向均有确认音）、`SFX.volSet(ch, idx)` 点选调档、`SFX.panelToggle()` 开合音量面板；`SFX.init(btn)` 自动接线——单击静音（面板展开时改为收起面板）、长按 450ms 或右键开面板、M 键静音快捷键（捕获阶段监听、输入控件内不响应）。
- **音量面板**：`#sfxPanel` role=dialog 懒创建挂 body（fixed top 96px right 16px，避让 top 60px 全屏键）——「全部声音」总开关 + ♪音乐 / ✦音效各 4 档点选条，全部中文文案；主题色经 `getComputedStyle(btn).color` 运行时注入 `--vol-accent`，8 页零主题色改动；面板外点击（捕获阶段）或 Esc 关闭。
- **嵌入协议收敛**：旧 `arcade:sfx` / `arcade:vol` 四消息并入单通道 `arcade:audio`（见 §2.3）——子页按钮/面板操作转发父页 `{act:'toggle'|'vol'}`、加载时以 `arcade:audio`（act=hello）报到，父页持久化后向全部 iframe 广播 `{m,b,s}`，权威状态唯一归父页。

**v2.3.1 修复（2026-10-22，音控交互修复）**

- **hello 握手指纹对齐**：子页报到报文由 `{type:'arcade:audio:hello'}` 修正为 `{type:'arcade:audio', act:'hello'}`——父页监听仅认 `type==='arcade:audio'`，原指纹永不匹配致握手静默失效（子页加载后取不到父页权威状态）。
- **长按阈值 350→450ms**：原阈值贴近慢速点击时长，按住略超即误判长按弹面板并吞掉本次 click（`lpFired`），造成「点击无效果」的体感。
- **静音方向补确认音**：`muteCore()` 在翻静音旗前先播 880→392Hz 下滑确认音（翻旗后 `ensure()` 短路无法出声，必须先播）；恢复方向保留 660Hz 上滑确认——两个方向点击均有可听反馈。
- **面板开合语义**：面板展开时单击主键改为收起面板（不再误切静音，总开关走面板内按钮）；面板标题栏新增 ✕ 关闭钮（`.sfx-head` 改 flex 两端对齐）；主按钮加 `user-select:none` / `-webkit-touch-callout:none` / `touch-action:manipulation` 防移动端长按误选与系统呼出，`:active` 缩放 0.94 给出按压反馈。

### 3.4 gamepad.js —— 手柄支持库（243 行，2026-11-04 新增）

全局暴露 **`GP`** 对象（`{ connected }` 最小状态，库自治运行、页面侧零调用零改动），为全站 8 页提供手柄支持——Gamepad API 与街机厅形态天然契合，本库把手柄输入**边沿触发**地合成为标准 `KeyboardEvent` 派发到 document，大厅导航与各游戏的方向键 / AB 键位**零改动**即可用手柄游玩（不修改任何页面协议与键位处理逻辑）。

**工作方式**

1. **rAF 轮询**：`requestAnimationFrame` 循环读取 `navigator.getGamepads()`（该 API 为轮询式，按钮 / 摇杆即时值只在轮询时刷新，无原生按键事件）；页面隐藏时跳过轮询。
2. **边沿触发**：对比上一帧状态——按键松开→按下派发一次 `keydown`、按下→松开派发一次 `keyup`，**不模拟连发**（各游戏普遍过滤 `e.repeat`，按住=一次 keydown 与原生键盘状态模型一致，天然兼容俄罗斯方块 DAS/ARR 按住机制）。
3. **标准事件同构**：合成事件同时携带标准 `key` 与 `code` 双属性（方向键 key==code、空格 key=`' '` code=`'Space'`、字母 key=`'p'` code=`'KeyP'`），与真实键盘事件完全同构——各游戏按 `e.key` 或 `e.code` 监听均可命中；fx.js 键帽高亮面板按 `e.code` 点亮亦自动联动。
4. **派发目标 document**：事件路径覆盖三类监听位置——window capture（audio.js 静音 / fullscreen.js 全屏）、各游戏 document 监听、大厅 window 监听（投币），全部正常接收。

**映射表（标准手柄布局）**

| 手柄 | 合成键 | 语义 |
| --- | --- | --- |
| 十字键 12/13/14/15 + 左摇杆 axes[0/1] | ↑ ↓ ← → | 大厅卡片导航 / 各游戏方向键（摇杆 0.5 触发 / 0.35 释放双阈值滞回防抖） |
| A（buttons 0） | 空格 | 射击 / 硬降 / 蓄力 / 暂停（贪吃蛇·华容道暂停本即空格） |
| B（buttons 1） | Esc | 关闭成就墙 / 音量面板等弹层 |
| X（buttons 2） | P | 暂停 / 继续（五款游戏，另两款暂停即空格） |
| Y（buttons 3） | C | 成就面板 / 暂存（俄罗斯方块 Hold） |
| Select（buttons 8） | M | 一键静音 / 恢复 |
| Start（buttons 9） | 回车 | 大厅投币 / 吃豆人与 1024 的面板确认 |

> 右摇杆 / 扳机 / L3 R3 无惯用街机语义，不映射防误触。俄罗斯方块的成就面板（V）与小蜜蜂冲刺（Shift）暂无手柄键位，键盘专属。

**工程要点**

- **file:// iframe 授权**：Gamepad feature policy 默认仅 `'self'`，http(s) 同源部署 iframe 天然可用；file:// 直开时各帧为 opaque origin，需大厅 index.js 创建 iframe 处 `frame.allow = 'fullscreen; gamepad'` 显式授权（已同步处理），否则 iframe 内拿不到手柄数据、手柄在游戏内失效。
- **卡键兜底三通道**：`gamepaddisconnected` 事件 / 页面 `visibilitychange` 转后台 / 轮询侧发现手柄消失——统一 `releaseAll()` 补发全部 keyup，防止俄罗斯方块 DAS 左右键等「按住状态」跨场景卡死。
- **连接提示 toast**：`gamepadconnected` / `gamepaddisconnected` 顶部居中提示条（样式库内注入，霓虹绿描边对齐街机视觉，2.6s 自动淡出；`prefers-reduced-motion` 下免过渡直接隐没）。
- **合成事件不产生 user activation**：AudioContext 自动播放解锁仍需首次真实点击 / 按键（audio.js `warm()` 在真实手势后自动补启）；大厅待机态手柄任意映射键按下即触发「按任意键投币」——拿起手柄按键即可唤醒街机。

## 4. 大厅页实现

`index.html`（1416 行，纯结构 + 样式）+ `index.js`（2015 行，大厅逻辑脚本，2026-11-04 由内联脚本外置）共同组成大厅，逻辑按模块划分：

**视觉层**

- `body[data-fs-keep-title]`：声明 keep-title 全屏模式。
- `#crtBoot`：CRT 开机动画层（黑幕 → 白线 → 白幕），一次性播放，三层编排精修（2026-10-20）：**黑幕掩护退场**——`crtBlack` 在 80% 保持不透明、80%→82% 快速退场（约 21ms），此刻白幕 `scaleY` 已撑至近满屏恰将黑幕完全遮盖、切换无感知；若黑幕与白幕同时淡出，揭幕中段两半透明层叠加、对比度塌陷画面发灰。**分段缓动**——`crtLine` 各关键帧内逐段声明 `animation-timing-function`（作用于该帧到下一帧的插值段）：0~28% 白线亮起 ease-out，44%→82% 撑满段 `cubic-bezier(0.72, 0, 0.28, 1)` 强 in-out（蓄力-爆发-柔停），82%→100% 淡出段 `cubic-bezier(0.22, 0.61, 0.36, 1)`（easeOutCubic 快起慢收）。**通电微闪**——白线亮起后 34%→44% opacity 1→0.86→1（约 63ms 跌 + 105ms 回），模拟老显像管电压不稳；微闪帧须显式带上 `transform: scaleY(0.002)`（keyframes 各属性沿最近声明帧独立插值，漏写会使白线在微闪期间缓缓撑开）；`::after` 辉光同步增强（24px/0.85 → 32px/0.9）。白线撑开动画用 `transform: scaleY` + `opacity`（合成器属性，GPU 合成线程推进），不动画 `height` 等布局属性；且开机窗口（约 0.85s，白幕动画 82% 处开始淡出前）内大厅各动效循环由 `lobbyFx` 挂起（见下文），主线程全力服务整页首次光栅化与 Press Start 2P 字体加载（`<head>` 内 preconnect googleapis / gstatic 两跳域名让字体尽早就绪，避免 `display=swap` 的换字回流恰好砸在白幕阶段），避免开机白幕卡顿。

- **卡带式进入过渡**：`openGame(url, glowRgb)` 先在覆盖层内铺 `.overlay-loading` 占位层（像素风「LOADING」文案 + 辉光色取自入口卡片主题色，经 CSS 变量 `--loading-glow` 注入）；iframe `load` 事件与最短展示时长 `MIN_LOADING_MS = 450ms` 二者取晚再揭幕，防白屏闪烁；`LOADING_TIMEOUT_MS = 8000` 超时兜底强制进入；揭幕时 iframe 加 `.frame-in`（0.35s 淡入）、loading 层加 `.loading-out`（0.4s 淡出）交叉过渡，动画结束后移除占位层。入口 URL 已带 `?v=` 时改拼 `&embed=1`，避免覆盖既有版本号参数。
- **活的大厅会“待机”**：全局动效开关 `lobbyFx`，有两个 false 窗口。① CRT 开机遮罩期间：初始即为 false，约 0.85s 后（白幕动画 82% 处即将开始淡出）由 `setTimeout` 恢复 true——开机瞬间整页首渲染 + 字体加载是主线程最重的时刻，星空/7 个预览 canvas/光晕等约十个循环若同时启动会满帧空转抢预算、挤压白幕动画的合成调度，挂起它们让主线程全力服务首屏光栅化，揭幕瞬间大厅已处于活动状态、衔接无缝；② 游戏覆盖层打开期间：`openGame` 揭幕前置 false 并给 body 挂 `game-open` 类（CSS 侧冻结卡片浮动、预览呼吸等 8 类动画）。JS 侧 9 处 rAF 循环（星空、7 张卡片预览、光晕插值）统一以 `if (!lobbyFx.active) { last = t; requestAnimationFrame(tick); return; }` 守卫挂起并重置时间基准，保证恢复瞬间不跳帧（光晕循环为帧率无关插值、不依赖 dt，恢复后从当前位置平滑追随）；`closeGame()` 在关机演出启动时即恢复 `active = true` 并移除类，黑底淡出露出的大厅已是活动状态（见下条）。
- **CRT 关机退出演出（2026-10-20 新增）**：`closeGame()` 告别 0.3s 生硬淡出，改为与开机白幕镜像呼应的三层编排（`#gameOverlay.overlay-out`，总时长 0.55s）——① 画面坍缩：iframe `crtShrink` 0→55% 纵向坍缩为过曝亮线（`scaleY(0.003)` + `brightness(2.4)`，强缓入 `cubic-bezier(0.62, 0, 0.84, 0.34)` 加速收束），55%→100% 横向收束熄灭（`scaleX(0.08)` + `brightness(3.2)`）；② 白热余辉：覆盖层 `::after` 白色束层 `crtDie` 30%→52% 亮起接管、64% 驻留后随黑底同步熄灭（辉光参数与开机 `#crtBoot::after` 一致）；③ 黑底揭幕：`overlayOut` 0~64% 保持不透明托住坍缩全程、64%→100% 淡出露出大厅——画面熄灭与揭幕节奏错开，避免「还没关机就漏光」。✕ 按钮 `closeBtnOut` 0.15s 提前隐去。工程要点：子动画的 `animationend` 会冒泡到覆盖层，收尾监听必须按 `e.target === el` 过滤（否则 ✕ 按钮 0.15s 先结束会提前摘除整层），且不可用 `{ once: true }`（子事件会消费掉监听器），配 600ms 兜底强制移除防系统禁用动画等极端场景。

**关气回流缩略（2026-11-04 新增）**

- **演出编排**：`closeGame()` 下发 `arcade:save` 后同步截取游戏画布末帧——遍历 iframe 文档取像素面积最大的 `<canvas>`（辅助层小画布自动跳过）`toDataURL('image/png')`，随后按 FLIP 反演启动回流缩略：缩略图 `<img>`（`.reflow-shot`，主题色经 `--reflow-glow` 取自卡片内联 `--glow`）先按目标卡片矩形落位，延时 0.28s（衔接 CRT `crtShrink` 55% 过曝亮线时刻）后以 WAAPI 三帧编排飞回——0% 以全屏宽纵向压扁亮线形态自原画面垂直中线起飞（与坍缩亮线无缝接棒）→ 30% 绽放撑满原游戏画面区域（末帧完整"回放"）→ 100% 缩放飞落卡片原位（duration 0.36s，"画面装回卡带"）；落卡后卡片挂 `.card-reflow` 辉光脉冲 0.65s 承接余温，缩略图 0.16s 淡出移除。总演出约 0.77s，落卡时刻覆盖层 0.55s 窗口已移除 90ms、大厅完全露出，衔接紧凑完整。
- **健壮性**：截图与动画全链路 try-catch 静默降级（跨源 iframe / canvas 污染等异常直接退回原 CRT 关机演出）；截图像素过小（`data.length < 128` 空画布）跳过；`prefers-reduced-motion` 不启动；落点卡片引用由 `openGame` 第三参传入记入 `openedCard`（module 级变量），`closeGame` 用后即清防异常路径残留。

**待机吸引模式（2026-11-01 新增）**

- **闲置自动演示**：大厅无任何输入持续 `IDLE_MS = 20000`（20s）后进入 attract mode——body 挂 `attract-mode` 类（非聚光卡片压暗失色、聚光卡片复用悬停视觉语言：上浮 + 霓虹发光），顶部降下 `#attractBanner` DEMO 横幅（「DEMO」字样 steps 跳变闪烁 + 当前聚光游戏名 + 「任意输入返回」提示，`pointer-events` 穿透不吞输入）；聚光每 `STEP_MS = 3400`（3.4s）轮换到下一张卡片，节奏接近街机演示换面。任意输入（键盘/鼠标/触摸）立即退出并摘类还原；打开游戏覆盖层、页面切至后台（`document.hidden`）期间不进入；`prefers-reduced-motion` 下 DEMO 闪烁与卡片压暗过渡停用（轮播退化为直接切换，功能保留）。

**音频驱动灯带（2026-11-04 新增）**

- **频谱→视觉映射**：index.js 末尾独立小 rAF 循环每帧 `SFX.level()` 读一次频谱（不动星空渲染主循环），低频能量经升快降慢的指数平滑（上行 0.45 / 下行 0.07）驱动 `#edgeBeam` 的 `brightness(1+b·0.9) saturate(1+b·0.5)`——鼓点越猛灯带越亮越艳；高频能量（上行 0.35 / 下行 0.05）驱动 `hue-rotate(t·70°)`，四色霓虹整体旋移流彩；投币口 `#coinSlot` 同帧叠加 `brightness(1+b·1.6)` 亮度脉冲（小面积辉光元素增益更高、脉冲感更醒目）。
- **状态守卫**：黑白待机（`pre-coin`）与点亮演出（`lights-on`）期的 filter 由 CSS 规则/动画全权负责（lightsOnPower 动画含 fill 覆盖、内联样式级联低于动画值，`lights-on` 摘类后动画声明失效、内联 filter 自然接管）——两态期间 JS 跳过写入；双双静默时清空内联 filter 回落 CSS 基态（无声音时零渲染开销）；游戏覆盖层打开期间（`lobbyFx.active=false`）挂起写入（子页声音来自其自身音频实例，父页频谱本就无声）；`prefers-reduced-motion` 下整个模块不启动（常驻灯带动画本已停住，频谱驱动一并禁用）。

> **暂停体系（全游戏统一：手动暂停 + 失焦自动暂停双能力）**：7 款游戏均具备两条暂停通道——玩家可随时按键手动暂停，且均监听 `window blur` 事件、窗口失焦即暂停、恢复输入继续。**即使是华容道这类回合制游戏也必须实现双暂停**：其用时统计（elapsed）参与评级与纪录，切窗/挂机若不冻结计时会虚增用时、污染纪录公平性。键位分布：snake / tetris / pac / pinball / 1024 五款走各自既有暂停通道（手动 P 或空格，blur → `togglePause()` 或等价置位）；bee 以 P 键手动暂停（空格已被射击占用）+ `blurPaused` 失焦标记，双标记独立、恢复一次清空（见 §5.2）；klotski 以空格手动暂停（P 已被演示最佳解占用）+ blur 置位同一 `isPaused` 标记，暂停冻结 elapsed 累加与演示步进（见 §5.2）。各游戏恢复时普遍配合 dt 限幅（§6）防止切回后跳帧。

> **进度镜像快照体系（2026-11-01 起，七游戏统一契约）**：每款游戏持有唯一存档键 `arcade_save_<id>`（snake / tetris / pac / bee / pinball / klotski / 1024，见 §7），键值 JSON 首字段恒为 `"v": 1`。`saveSnapshot()` 在对局进行中整体写入、非进行中移除键、异常静默（try-catch）；`restoreSnapshot()` 整体 try-catch + 逐字段合法性校验（版本号、枚举、数组形状、数值范围），任一非法即整键废弃返回 false，绝不带病恢复。**保存双触发**（2026-11-05 起由三触发收缩——返回链接随按钮移除而删除）：① 父页 `closeGame()` 关闭覆盖层前下发 `arcade:save` 消息（0.55s 关机动画窗口内送达，见 §2.3）；② `pagehide` 页面卸载兜底。**清除时机**：Game Over 结算、通关、玩家主动重开。**恢复防即死**：实时游戏（snake / tetris / pac / bee / pinball）恢复后置为暂停态、以暂停遮罩呈现，玩家按继续键接管（避免恢复瞬间即遭敌方弹幕/蜂群攻击）；回合制游戏（klotski / 1024）恢复后直接可玩并显示「已恢复上次进度」提示。各游戏快照字段见 §7 键表。

### 5.2 各游戏实现要点

**贪吃蛇 snake.js**（2026-10-22 渲染循环统一升级 / 2026-11-01 静态背景层缓存 + TDZ 修复 + 进度镜像快照 / 2026-11-04 每日目标 + 手感升级 + 自适应 BGM 分层，1538 行）

- 单 rAF 主循环（§6.1）：逻辑 tick 由毫秒累加器 `moveAcc` 驱动补帧推进（单帧补帧上限 4 防死亡螺旋），渲染层每帧以 `t = moveAcc / gameSpeed` 对蛇身**逐节插值**——移动从逐格瞬跳变为连续滑行。
- 插值快照：每次 tick 前 `prevSnake = snake.slice()` 浅拷贝（必须浅拷贝——后续 `unshift/pop` 原地变更数组，引用赋值会使 prev 与 cur 恒等、插值失效；元素对象入列后位置不变，浅拷贝即可）；成长出的新尾节以 `prevSnake[i] || seg` 原地绘制；穿墙 wrap 前后位置差超过 1 格（`|dx|>1 || |dy|>1`）判定为瞬移、不插值。
- 冻结语义统一：`updateLogic` 入口检查 `!isRunning || isPaused || achPanelOpen || isDying || FX.frozen()`，冻结时 `moveAcc` 定格 → 插值进度 t 定格——暂停半格悬停、hitstop 卡帧、死亡定格自然成立。
- 死亡演出时长 `DEATH_DURATION = 0.9s`。
- 金苹果机制：出现概率 `GOLD_CHANCE = 0.22`，存活 `GOLD_TIME = 5s`，得分 ×5。
- 静态背景层离屏缓存（2026-11-01，§6.4）：棋盘暗底（`#0f1a12`）与网格线绘入离屏画布 `gridLayerCanvas`（物理分辨率与主画布 1:1 对齐），`setupDisplay` 重适配时置位 `gridLayerDirty` 下一帧重建一次，主循环每帧单次 `drawImage` 贴回——静态底图不再逐帧重绘。
- 进度镜像快照（2026-11-01，§5.1）：`arcade_save_snake`（`v/diff/cols/rows/snake[]/dir/nextDir/food/score/eaten`），恢复后停暂停遮罩防即死。
- 每日目标（2026-11-04）：本地日期 YYYYMMDD 经哈希确定性映射当日目标长度（`DAILY_GOAL = 15 + hash % 16`，即 15~30 节，同日恒定），HUD STATS 增「今日」行实时显示已达长度 / 目标；当日达成即落盘 `arcade_daily_snake_<YYYYMMDD>`（读写 try-catch）并金色庆祝演出，次日自动换新目标。
- 手感升级（2026-11-04）：HUD 分数改 `FX.tweenNumber` 滚动补间（三处写值点：进食 / 金苹果 / 结算）；文件尾接入 `FX.playtime.init('snake')` 时长统计与 `FX.KeyLight.init()` 键帽高亮（html 键位面板键帽补 `data-code`）。
- 自适应 BGM 分层（2026-11-04，audio.js v3.0，§3.1）：`syncDangerLayer()` 按蛇身长度置危险态——≥15 节（对齐每日目标区间下限）`SFX.bgm.setIntensity(true)`，BGM 逐拍叠加低音鼓点声部；吃普通食物 / 金苹果成长后与续玩快照恢复（≥15 节直接进入危险分层）各调用一次同步，死亡必走 `bgm.stop()`（重开 `start()` 走重置分支）天然清态。

**俄罗斯方块 tetris.js**（2026-10-22 三件套计分升级 + 逆时针旋转/hitstop 手感升级 / 2026-11-01 静态网格层缓存 + 进度镜像快照 / 2026-11-04 硬降屏震 + 手感升级，1766 行）

- 消行得分 `LINE_SCORES = [0, 100, 300, 500, 800]` × 等级 × 难度倍率；软降 +1 分 / 硬降每格 +2 分；每 10 行升级并加速（`dropInterval = max(80, base - (lv-1) × 60)` ms）；无敌档堆到顶清空棋盘继续。
- **7-bag 随机袋**：7 种方块各一次装入袋中 Fisher-Yates 洗牌依次弹出，袋空重洗——每 7 块内 7 种各出现一次，杜绝纯随机的久等不出 I。
- **SRS 踢墙旋转（双向）**：JLSTZ 与 I 型各收录顺/逆时针 4 组转换共 8 组踢墙偏移表试移（含水平与上下），↑/W/X 顺时针、Z 逆时针（`rotatePiece(dir)` 方向参数化，`(from + dir + 4) % 4` 四态循环），贴墙/卡位旋转成功率远超旧版 5 级水平试移；T-Spin 判定对双向旋转同等生效（逆时针同样维护 lastActionRotate / lastKickIndex，判定逻辑零改动）。

- **锁定延迟 500ms**：触底后不立即锁定，移动/旋转可重置计时（上限 15 次防无限拖延），配合幽灵投影落点预览从容调整。

## 6. 渲染循环模式

七款游戏统一由单 rAF 驱动，逻辑推进按游戏特性分三种模式：

### 6.1 单 rAF + 毫秒累加器 + 逐节插值（snake）

```text
rAF 回调
  ├─ updateLogic(dtMs)：moveAcc += dtMs
  │    while (moveAcc >= gameSpeed) { moveSnake(); moveAcc -= gameSpeed }   // 补帧，单帧上限 4 防"死亡螺旋"
  ├─ t = min(1, moveAcc / gameSpeed)     // 当前 tick 内推进进度（0~1，帧率无关）
  └─ draw(t)：每节渲染位置 = lerp(prevSnake[i], snake[i], t)   // 逐节插值，移动连续滑行
```

逻辑节奏（`gameSpeed`）与帧率彻底解耦，难度只改 tick 间隔；渲染层在两 tick 之间线性插值，消除格子游戏的逐格瞬跳感。`prevSnake` 为 tick 前的**浅拷贝**快照（元素对象入列后位置不变，浅拷贝即可）；穿墙 wrap 时前后位置差超过 1 格，直接取目标格瞬移不做插值；暂停 / hitstop / 死亡演出期间 `updateLogic` 短路、`moveAcc` 定格，插值进度随之冻结。

**自愈式循环与看门狗（2026-10-22 加固）**：`renderLoop` 采用**前置排程**——进入帧首先 `requestAnimationFrame` 预约下一帧、再执行本帧逻辑，帧逻辑整体 try/catch（异常留痕后跳过本帧），单次异常不再杀死整条渲染链；配套 `loopWaiting` 挂起标志（帧首清零 / 帧尾置位）+ 每 2 秒巡检的渲染看门狗——仅当「循环无挂起帧（排程丢失或从未启动）**且**画布全透明（`isCanvasBlank()` 三点采样 getImageData，从未绘制）」双重条件成立才自动复活（`setupDisplay()` 重适配 + 重新拉起 rAF），画布保留历史画面或后台节流挂起（loopWaiting=true）均不误判。

> 历史架构（2026-10-22 前为 `setInterval` 逻辑 tick + rAF 渲染双循环）：定时器节拍与显示刷新不同步，蛇身逐格瞬跳、丝滑度差，已废弃，详见修改记录 2026-10-22 条目。

### 6.2 单 rAF + dt 限幅（tetris / pac / bee / klotski / 1024）

```text
rAF 回调内 dt = min(实际帧间隔, 0.05s)
```

限幅防止切后台回来后 dt 爆炸（一帧跳过整段棋局）。

1024 为回合制变体：游戏状态仅在滑动输入时推进（无逻辑 tick），rAF 循环只驱动表现层动画（插值、粒子、震闪），dt 限幅同样用于动画计时防爆。

### 6.3 单 rAF + 固定步长物理（pinball）

```text
外层：固定步长累加器（2026-10-21 升级）
  dt 限幅 0.033s → 累加进 accumulator
  while (accumulator >= FIXED_DT) { stepPhysics(FIXED_DT) }
  FIXED_DT = 1/120s（物理步长恒定，与帧率解耦）
  MAX_STEPS_PER_FRAME = 5（卡顿时丢弃多余时间，防"追帧螺旋"越跑越慢）
内层：速度自适应子步
  SUBSTEP_LEN = 6（每子步最大位移，世界坐标单位）
  MAX_SUBSTEPS = 12（单物理步内子步上限）
```

弹珠速度高（`BUMPER_KICK = 470`、球速上限 `MAX_SPEED = 980`）：外层固定步长让物理行为与刷新率解耦——任意帧率下轨迹一致、反弹可复现；内层按球速把每个物理步再拆细（每步位移 ≤6 单位），天然避免高速穿透挡板/弹跳柱/墙体。多球（`MAX_BALLS = 3`）下每球独立按同一步长推进。

### 6.4 静态层离屏缓存（snake / tetris / pinball / 1024，2026-11-01 起）

每帧不变的静态画面（网格线、台面装饰、空槽底格）不再逐帧重绘，而是绘入与主画布**物理分辨率 1:1 对齐**的离屏画布，主循环每帧以单次 `drawImage` 贴回后再绘制动态内容：

```
静态层生命周期：
  初始加载（脏标记初值 true）────────────┐
  setupDisplay 等置脏（画布重适配/DPR 变化）┤→ 下一帧 renderXxxLayer() 重建一次 → 清脏标记
  （1024 另含难度切换：SIZE/CELL 几何变化）┘
  稳态每帧：if (dirty) 重建 → ctx.drawImage(离屏层, 0, 0, 逻辑宽, 逻辑高) → 绘制动态内容
```

- **物理分辨率对齐**：离屏层 `width/height` 直接取主画布物理像素（`canvas.width/height`），层内 `setTransform(dpr,…)` 锁 CSS 逻辑坐标——绘制代码零换算、贴回零缩放，高 DPR 下网格线依然锐利。
- **重建时机收敛**：稳态运行零重建，离屏层 `width/height` 整个生命周期只写一次（1024 难度切换因槽位几何变化额外重建一次）。
- **收益**：静态绘制从每帧 N 次 fill/stroke 降为每帧 1 次 drawImage；harness 实测（DPR=2、6 帧驱动、录制型 context 计数）稳态每帧 Canvas 调用总数 snake 19 / tetris 7 / pinball 246 / 1024 220，四款每帧 drawImage 均恰 1 次、离屏层尺寸各置 1 次。

## 9. 部署说明

### 9.1 启动

```bash
python server.py        # 监听 0.0.0.0:8765
# 浏览器访问 http://localhost:8765
```

### 9.2 实现要点（[server.py](../server.py)，56 行）

- `ThreadingHTTPServer`：多线程处理并发请求。
- 自定义 `NoCacheHandler.end_headers()`：每响应追加三重禁缓存头

  ```text
  Cache-Control: no-cache, no-store, must-revalidate
  Pragma: no-cache
  Expires: 0
  ```

  保证开发期改动即时生效，配合 §8 的 `?v=` 双保险。

- 启动期自动运行 §9.4 静态一致性检查（`run_startup_check()`）：`python server.py` 起服即检七项站点约定（毫秒级、一次性，不进请求路径）；检查失败仅打印醒目警告、不阻断起服，tests 目录不在位时静默跳过。

### 9.3 其他运行方式

纯静态站点，任意静态服务器（nginx、`npx serve` 等）均可承载；但需自行保证禁缓存头，否则版本号策略成为唯一破缓存手段。

### 9.4 静态一致性检查（[tests/check.py](../tests/check.py)）

- 零依赖纯 Python 3 标准库（与 server.py 同工具链），对本项目全部 `*.html` / `*.js` 做静态扫描，`python tests/check.py` 一键运行：全绿退出码 0，存在失败项退出码 1 并逐条打印明细。
- 七项检查：①HTML 本地 `src`/`href` 引用完整性；②本地 js/css/html 引用须带 `?v=` 指纹；③每页公共库 `audio → fx → fullscreen → 业务 js` 加载序；④危险模式（`eval(` / `new Function(` / `document.write(`）零命中；⑤localStorage 直接读写的文件须含 try-catch 兜底（文件级粗检，对应 §5 全站容错约定）；⑥大厅七卡片入口与各游戏 html/js 文件齐全；⑦浏览器兼容性——前缀敏感 CSS 属性（`user-select` / `backdrop-filter` / `mask-composite` / `mask` 简写）的无前缀形式出现时，同文件必须存在 `-webkit-` 成对写法（Safari 旧版需前缀、Firefox/Chrome 吃无前缀，成对两侧通吃），`AudioContext` 构造必须带 `webkitAudioContext` 回退（Safari 14.1 前仅暴露带前缀构造器；仅约束构造用法，注释提及不约束避免误报）。

- 定位：改动 html / js 后提交前运行一遍全绿即视为结构一致（对应 §8 更新规则第 4 条）；本仓库当前未 git 化、无 pre-push 钩子可用，起服即检即日常守护——若未来推上 git 托管平台，可将 `python tests/check.py` 挂为 pre-push 钩子或 CI 步骤。
- Firefox / Safari 手动回归清单（检查项 7 只能静态守护前缀成对，动态行为仍需人工验证；Edge/Chromium 为主力开发环境）：

- tests/check.py（§9.4）为纯静态文本检查，无法验证事件时序、状态机流转等运行时行为——2026-11-04 成就墙关闭误触投币的监听时序缺陷即漏网于此。本页补足行为级验证：在真实浏览器中以同源 iframe 加载真实页面、派发合成 DOM 事件（`PointerEvent` / `KeyboardEvent` / `click`）、断言真实副作用（body 类名、面板 `hidden`、localStorage 存档、`postMessage` 报文）。
- 零依赖：无 node / playwright，与项目工具链（纯浏览器 + Python 标准库）一致，无构建步骤。
- 运行：`python server.py` 起服后浏览器访问 `http://localhost:8765/tests/smoke.html`，页面自动串行执行全部 14 场景（约 10s）；**file:// 直开不可用**（同源策略阻断 iframe 内部访问）。
- 自动化契约：结果实时渲染于 `#summary` 总结条与 `ol#results` 列表，并同步暴露 `window.SMOKE_RESULTS`（`[{ name, pass, detail }]` 数组）与 `document.title`（「冒烟通过 14/14」/「冒烟失败 n/14」）；「重新运行」按钮可重入（running 标记防并发重跑）。

### 11.3 数据安全与实现要点

- localStorage 保护三步：启动时快照全部键值 → 清空并种入测试数据 → 结束原样恢复（`finally` 与 `pagehide` 兜底双路 + 幂等标记防重复恢复）——测试种子与成就章（`__smoke_a` / `__smoke_b`）不污染真实存档。
- 场景间销毁全部 iframe（状态彻底隔离）；每场景 iframe 查询串拼 `r=序号` 绕缓存保证全新加载，路径已带查询串（`?embed=1`）时以 `&` 续接避免双 `?`。
- `loadPage` 等 load 事件后再稳定 350ms（各模块监听挂载完成）才派发事件；`fire` 在 iframe body 上派发冒泡事件，沿 body → document → window 命中两条路径的全部监听。

### 11.4 维护约定

- 改动投币门禁 / 成就墙 / 嵌入协议 / 成就写入等时序敏感逻辑后，与 check.py 一并运行全绿再提交——静态检查管结构一致（§9.4），冒烟测试管行为正确，二者互补。
- 新增关键交互（时序敏感 / 状态机 / 跨帧协议）时按既有模式追加场景：`loadPage → fire → ok` 三步自包含、抛错即败；场景数变化同步更新本节清单。
